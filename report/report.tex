\section{Executive summary}

Departments at IITM assign lecture slots by hand-editing last year's slotbook. Nobody can then say why a course got its slot, or what a clash would cost to fix.

We shipped a Java engine that validates five CSV inputs, solves with UniTime's cpsolver (an exact CP-SAT model is kept as a reference), and writes the slotbook with a reason for every assignment and every rejected slot. Students and professors enter preferences on a Vercel portal backed by Postgres, which also warns about missing prerequisites using the student's grade card. The timetabler downloads the CSVs from the admin page, runs one command, and publishes the result. \section{Known limitations}

\begin{itemize}[leftmargin=*,nosep]
  \item \textbf{Optimality.} The default UniTime solver is a heuristic: on 3 of the 13 generated scenarios with a proven optimum it finished 1--8 points above CP-SAT (30 against 26 when instructors are shared). \texttt{--solver cpsat} is needed for a guarantee.
  \item \textbf{No identity on the portal.} Anyone can submit under any student ID, and grade cards are self-uploaded and unverified, so warnings are only as trustworthy as the uploader. It is not fit for real student data until IITM login exists.
  \item \textbf{Fixed rooms, one PDF layout.} Each course keeps its given room and capacity is not modelled. The grade-card parser reads only the IITM PDF's text layout, so scanned or photographed cards are rejected.
\end{itemize}
