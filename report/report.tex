\section{Executive summary}

IITM departments assign lecture slots by hand-editing last year's slotbook, so nobody can say why a course got its slot.

We shipped a Java engine that validates five CSV inputs, solves with UniTime's cpsolver (an exact CP-SAT model is kept as a reference), and writes the slotbook with a reason for every assignment and every rejected slot. Students and professors enter preferences on a Vercel portal backed by Postgres, which also warns about missing prerequisites using the student's grade card. The admin's ``Generate slotbook'' button runs the engine as a web service and publishes the result. \section{Known limitations}

\begin{itemize}[leftmargin=*,nosep]
  \item \textbf{Optimality.} UniTime is a heuristic: on 3 of 13 generated scenarios it finished 1--8 points above the CP-SAT optimum.
  \item \textbf{No identity on the portal.} Anyone can submit under any student ID, and grade cards are self-uploaded and unverified. It is not fit for real student data until IITM login exists.
  \item \textbf{Fixed rooms, one PDF layout.} Rooms are fixed per course; capacity is not modelled. The grade-card parser reads only the IITM PDF's text layout, so scanned or photographed cards are rejected.
\end{itemize}
